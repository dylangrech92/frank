`normalize_event` is defined in `relay/handlers/transform.py` and reaches the rest of the codebase through several different paths, not just one.

First, `normalize_event` is registered on the event bus via the `@bus.on(EVENT_ORDER_CREATED)` decorator, so `normalize_event` fires whenever `bus.publish(EVENT_ORDER_CREATED, event)` runs during the pipeline's transform stage -- this is the only caller that never imports `normalize_event` by name at all. Second, every enrichment plugin calls `normalize_event` directly as a normalization pass before doing its own work. `relay/plugins/builtin_enricher.py` imports and calls `normalize_event` (the active default plugin). `relay/plugins/premium_enricher.py` also imports and calls `normalize_event`, even though it is only an alternate, non-default plugin. `relay/plugins/discount_enricher.py` likewise imports and calls `normalize_event` directly, again as a non-default alternate. Third, there is an aliased path: `relay/compat/legacy.py` re-exports `normalize_event` under the old name `clean_event = normalize_event`, and `relay/handlers/delivery.py` imports `clean_event` from that compat shim and calls it during final delivery, so that call site never mentions `normalize_event` in its own source at all.

Finally, there is a second aliased path, separate from `clean_event`: `relay/compat/legacy.py` also re-exports `normalize_event` under a different old name, `sanitize_order = normalize_event`, and `relay/sinks/webhook_sink.py` imports `sanitize_order` from that compat shim and calls it before writing the webhook outbox record -- so, like the `clean_event` path, this call site never mentions `normalize_event` in its own source.

One thing deserves a specific note: `relay/plugins/geoip_lookup.py` defines its own, separate function also named `normalize_event`, but it takes a plain dict and returns a new dict rather than mutating an `Event`, and it is never imported anywhere else in the project -- it is an unrelated, coincidentally-named leftover, not part of this caller set.

1. ledger/importer.py — `_read_csv_rows` catches `OSError` and returns `[]`, silently discarding the exception with no logging and no error record, so a permission-denied or unreadable `transactions.csv` is indistinguishable from "no data".
2. ledger/validators.py — `validate_swift_bic` is dead code: it is fully implemented but never called anywhere in the codebase.
3. ledger/validators.py — `classify_amount`'s final `else` branch returning `"unknown"` is unreachable, because `parse_amount` only ever produces finite floats, so every possible value already matches one of the earlier conditions.
4. ledger/config.py — the `strict_duplicate_check` config flag is parsed from JSON but never read anywhere else in the codebase; it has no effect on import behavior. Unused config flag.
5. ledger/aggregator.py — `summarize_by_category` declares a mutable dict default argument, `running_totals: dict[str, float] = {}`, so category totals accumulate and leak across separate calls that don't pass their own dict explicitly, such as when the `aggregate` command processes multiple batch directories in one process.
6. ledger/aggregator.py — `top_movers` sorts `cached_transactions` with `.sort()` in place; since `reports.py` passes `batch.transactions` directly rather than a copy, this mutates the batch's own transaction list as a side effect, corrupting the order that `recent_activity_rows` relies on afterward — recent_activity is no longer chronological once top_movers has run.
7. ledger/aggregator.py — `reconcile` compares `computed_total == account.expected_closing_balance` using float `==`, which fails for balances that are mathematically equal but differ by ordinary floating-point rounding drift (reproducible with the sample data's ACC1001).
8. ledger/cache.py — `AccountCache` is keyed by `account.name` instead of `account_id`; when two accounts share the same name (ACC1001 and ACC1003 in the sample data both have not-unique names), `lookup()` returns the wrong account's cached entry.
9. ledger/paginator.py — `get_page` has an off-by-one: when the item count is an exact multiple of the page size, the computed page boundary ends one short (`end = total - 1`), so the final record is silently dropped from every page.
10. ledger/timezones.py / ledger/reports.py — `daily_totals_rows` buckets each transaction's calendar day using an account's UTC offset obtained once from `cached_utc_offset_minutes` at import time and never re-derived per transaction date; for a transaction whose own date falls on the far side of a daylight saving (DST) transition from the account's import date, the stale cached offset produces the wrong calendar day.
